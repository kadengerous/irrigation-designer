# Automatic engineering routes

Auto routes save their geometry, capture distance and circuit; hydraulic edges are derived from current project consumers. Existing manual pipes retain their assigned diameter. Sprinklers use the existing catalog flow and working pressure; custom outlets/drip starts require explicit flow and pressure. Hidden consumers still consume water. Unknown demand blocks a completed pump recommendation.

New auto routes can start anywhere, with any number of freely drawn supply points before the first sprinkler. These approach points stay fixed; only the subsequent sprinkler lateral is offset. Sprinklers are selected in order, within one zone. A single sprinkler is sufficient when a supply approach exists. A double click/tap on the last selected sprinkler finishes on mouse, pen and touch. The sprinkler lateral is offset 0.50 m. A containing irrigated plan figure helps choose the inward side, but belonging to one figure is never a precondition for completion. Parallel segments use joined corners; open ends at sloped lawn corners are trimmed along the parallel line to the contour; the route and flexible connections are checked against the actual contour, holes and non-irrigated obstacles. If no common contour fits, choose between the parallel offsets using the irrigated portions of the plan and the selected sprinklers’ sector direction, with obstacle avoidance as a preference. Completion still saves an editable route, including across separate figures, with stale figure IDs, or without plan geometry. This is not obstacle-routing; inspect the route when the plan offers no unambiguous inward side. Only selected heads are connected. Other zones and heads owned by another route are rejected when explicitly selected. Free waypoints are accepted before, between and after sprinklers. A waypoint route retains the exact drawn path and captures visible, unowned sprinklers within 1 m along its segments, in one zone; thin preview branches show these connections before completion. It does not zigzag through captured sprinkler centres or receive an additional inward offset. The all-centre workflow still uses the 0.50 m inward offset. Waypoint routes save explicit consumer IDs and pathMode=waypoints, so later nearby routes cannot steal these sprinklers. Double-tap the last free point or sprinkler to finish; the same mouse, touch and pen completion handlers apply. Extending a saved route preserves its existing geometry and owners. A saved headStartIndex separates the supply approach from the sprinkler lateral, so branches connect to the lateral rather than jump onto a nearby supply segment. Node insertion/removal preserves this boundary. Touch uses a 10px movement threshold and a 600ms double-tap interval; a native mouse double-click also completes at the last head, without creating a second route. No new completion button is introduced; the existing route controls and Enter/Escape remain available.

Legacy auto routes retain nearby-consumer capture: the first nearby consumer determines the default circuit, and only that circuit is captured. Existing consumer ownership is saved in consumerIds. A later route never steals consumers. Legacy routes claim in creation order on the next engineering commit. Dragging a route preserves its consumers and recomputes connection geometry during the live preview. Zone route starts join a shared main; unmarked crossings and neighboring zones do not connect. Main source defaults to the first auto route start, or a selected source equipment port. One source, acyclic networks only; loops and disconnected consumers block a result. Hydraulic equipment ports are junctions, not valve/control simulations.

Pipe basis is PE100 SDR11, outside diameters 20–110 mm with table minimum wall thickness. Sizing uses inside diameter, peak downstream scenario flow and a maximum 1.5 m/s velocity. Sequential operation sizes shared trunks for the largest zone flow; simultaneous operation sums all circuits. This is velocity-based sizing, not economic optimization or a pressure-balancing solver.

Friction uses SI Hazen–Williams, C=140, including automatic connection branches. Thin on-screen branches are connection symbols; their visual width does not define hydraulic inside diameter. Flexible hose and fitting losses remain part of the explicit extra-loss input. Required head combines the worst consumer's working pressure, its path losses, terminal velocity head, explicit maximum static lift and explicit extra losses, minus inlet pressure under flow. Extra losses must include fittings, filters, valves, housings/regulators and suction components. A zero value must be entered explicitly. All project consumers must be connected for a completed result. Pump summary is a conservative Q–H duty envelope; compare each zone duty against a real pump curve. It does not select a pump model, motor power, verify suction/NPSH, model transients or establish pressure regulation at every emitter.

SI project values remain unchanged when display units switch. Auto settings participate in the existing engineering commit, undo/redo and project-file persistence.

## Network takeoff

The Networks panel lists geometric route length and totals by outside diameter without waste allowance. Sprinkler connection stubs are excluded from PE pipe totals and counted separately as flexible connections. Other consumer PE branches remain in the pipe totals. The shared estimate and PDF/XLSX/Word exports add 15% once to each diameter total and to flexible connection length. Each connected sprinkler gets one saddle using the PE diameter at its connection and the actual body inlet thread (never the nozzle thread), and at least 0.40 m flexible connection or its longer drawn offset. Saddles are counted as pieces without length reserve. Unknown diameters/inlets or ACME connections are flagged for review and not silently assigned invented fittings. No product SKU or price is invented. Custom flexible connection lengths and inlet sizes identify a takeoff requirement, not a manufacturer-rated hose selection.
